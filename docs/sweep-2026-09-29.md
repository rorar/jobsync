**How to use this file.** This is an evidence index, not a tracker. It records where each sweep finding

## 1. Method and scope

**The closed universe.** Every Claude session whose working directory was a jobsync checkout, or that
touched jobsync, and that was active between 2026-08-20 and 2026-09-28:

| Covered | How |
|---|---|
| 10 dialogue sessions (one turned out not to touch jobsync) | Every user message, regular and queued; every agent call; every marker block; the tail of every agent's final report |
| The E2E fixer session | Through its notes file, `E2E-FIX-NOTES.md` |
| 114 sub-agent transcripts, 13 of them stored under `<session>/subagents/` | Read through their parents; each agent's full final report compared with what the parent received |
| 176 automatic security reviews | 165 inside the window plus 11 from 2026-08-06 .. 08-19; each finding checked against the code and the trackers |
| Documents | All handoffs 2026-08-18 .. 2026-09-14, `docs/TASKLIST-2026-08-26.md`, the WH-B3 retention analysis, the two E2E analyses of 2026-09-06, `E2E-FIX-NOTES.md`, and two out-of-repo notes (a host-migration note and a session summary) |

**Excluded, and why.**

- Sessions before 2026-08-20. Their open work already lives in `docs/BUGS.md` and `CLAUDE.md` § Deferred
  Sprint Work.
- The April/May analysis documents under `docs/reviews/` and `docs/*-analysis.md`, for the same reason.
- Other projects.

**What the method cannot see.**

- A finding that was said aloud and never written down, in a transcript, a file or a commit.
- A finding held by an agent that left no transcript. One such agent exists (E11 in § 3); the three
  targets it was given are closed by `64e2f52d`.

**Marks.** A finding is *LOST* when it existed only in agent output that no working session received. It
is *open-absent* when a working session saw it and no tracker holds it.

**Transcript anchors.** The probe reports cite session ids and transcript lines (`L<n>`). Those files exist
only on the machine that ran the sweep. They are collected in Appendix A and nowhere else in this file.

## 2. Process failures, and the lessons they carry

The sweep found three ways in which work was lost, plus two gaps in its own first extraction. Almost none
of the 68 defects filed on 2026-09-29 is new code; most had been found once already.

| # | Failure | What happened | Reusable lesson |
|---|---|---|---|
| 1 | **Agent reports reached the lead truncated.** | Under Claude Code 2.1.246 an agent's idle notification carried no `result` at all, so six final reports reached the lead as 0 characters. From 2026-08-31 the notification carried the text, cut at about 4,000 characters, ending in "result truncated — ask the agent for the rest". The lead asked for some tails and not for others. In one case a message was lost because its sender was stopped nine seconds after sending it. Every LOST finding in § 3 that came from an agent sat in output the lead never received. | Treat the notification as a pointer, not the result. Have every agent write its full report to a file before it finishes, and read that file (or the agent's own transcript), never the notification. |
| 2 | **Security-review findings never reached a working session.** | The automatic security-review hook produced five findings between CLI 2.1.241 and 2.1.270. None of them reached a session that could act. Two were fixed later by work that found them again (H-S1, H-S2), one was accepted independently in ADR-046 (H-S4), and two were simply lost until this sweep (H-S3, H-S5). Two further reviews, of the retention-erasure change and of a weed-fix commit that extended the anonymise cascade, ended without any verdict (H-unrev). The cause is not established. | A review channel needs its own reader. Check that each review produced a verdict; an empty review is not a pass. |
| 3 | **"Done" was measured against what the lead had seen.** | On 2026-09-08 and again on 09-09 the user asked for every side finding to be fixed. The lead replied that all 17 were done. Six were still open (F-08-28), although they were in the visible part of agent reports. | Count "done" against the written list of findings, not against memory of the conversation. |
| 4 | **The sweep's first extraction missed two sources.** | Queued prompts (`queued_command` attachments and `queue-operation` entries) and sub-agent transcripts stored under `<session>/subagents/` were not in the first pass. Both were caught and covered in a second pass before consolidation. | An extractor needs a completeness check against a second, independent count of the same source. |
| 5 | **The ID-to-destination list truncated ten IDs.** | Found while writing this file: the list that maps sweep IDs to destinations holds ten family prefixes (`F-04`, `G-13`, `H9` …) instead of full IDs, and seven keys that are not finding IDs at all. Section 3 resolves every one of them. | Match the full ID grammar, and check the extracted IDs against the source list in both directions. |
