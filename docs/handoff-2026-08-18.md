## 2. Environment — read before running anything heavy

This host was tanked twice in the last session. Cause and cure are both known:

- **A dev server left running holds ~5GB (31% of RAM).** With it running, the full Jest suite was
  SIGTERM'd after 35 suites and one spec file alone took 457s. With it stopped, the same suite runs
  **179s, 308/308 green**. `bash scripts/stop.sh` now actually stops it (and verifies); `dev.sh`
  delegates to it, so restarts no longer orphan workers.
- **The "never stop the dev server" rule is narrower than it reads.** It targets sub-agents killing a
  server while a sibling runs tests — it is not a blanket ban. Idle server + contended box → stop it.
- **Do not stack heavy jobs.** One at a time; check `uptime` / `free -m` first.
- **`scripts/typecheck-safe.sh` does not complete on this host** — `EXIT:124` at 600s *and* at
  `TSC_TIMEOUT=1500`. Nothing on this branch has had a full type check. Use targeted LSP / serena
  `get_diagnostics_for_file` on changed files instead, and **say so** rather than implying tsc passed.
- **Judge exit status from the log, not the wrapper.** Three separate false-greens last session:
  `cmd | tail; echo $?` reports `tail`'s status; a background wrapper returned 0 over `EXIT:124`; and
  `stop.sh` printed "Stopped" while the process lived. Grep the log for the real summary line.
